### 1. mrbizarro/Phosphene
링크: https://github.com/mrbizarro/Phosphene  ⭐ 503 · 최근 push 2026-11-28 (MIT, 현재 v5.0.94)

**뭐 하는 건데:** Apple Silicon 맥에서 LTX-2.5, MiniMax H3 같은 공개 모델을 MLX로 돌려 텍스트/이미지→영상(소리 포함), 립싱크, 이미지 편집, Qwen3-TTS 음성, 타임라인 편집을 오프라인으로 한다. 자기 사진 15~50장으로 캐릭터 LoRA를 맥에서 학습시켜 LTX 샷에 넣을 수 있고, Claude Code용 MCP 서버와 로컬 HTTP API가 있다. (README 확인)

**미아한테 왜:** 지금 Nano Banana로 픽사풍 유피 이미지를 만들고 Kling 크레딧을 써서 움직이는 단계를, 유피 캐릭터 LoRA를 한 번 학습시켜 두고 맥에서 시안 클립을 크레딧 걱정 없이 여러 개 뽑는 방식으로 바꿀 수 있다. MCP가 있어서 Claude Code에 "이 이미지로 5초 클립 3개 뽑아줘"라고 시키는 것도 README상 가능하다.

**바로 해볼 것:** README의 "Will my Mac run it?" 페이지에서 내 맥 메모리로 뭐가 되는지 확인한 뒤, 맥 앱을 설치하고 기존 유피 픽사풍 이미지 한 장을 Image 모드(LTX-2.5)에 넣어 5초 클립을 뽑아 Kling 결과와 비교한다.

**걸리는 점:**
- 메모리가 성능을 좌우한다. 16GB면 LTX 작은 해상도만, 캐릭터 학습은 24GB 이상, LTX 풀사이즈는 48~64GB. 미아의 맥 사양을 몰라서 실제로 어디까지 될지는 미확인.
- 느리다. README 중앙값 기준 5초 클립이 M4 16GB에서 약 10분 40초, M4 Max 64GB에서 약 3분. Kling 대비 품질은 직접 돌려보지 않아 미확인.
- 디스크를 많이 먹는다. 설치 18GB + LTX 약 27.5GB, H3까지 받으면 약 75GB 추가(외장 드라이브 지정 가능).
- 모델별 라이선스가 따로다. README상 MiniMax H3 라이선스는 EU·영국·한국·미국을 커버하지 않는다(호주는 명시 없음). 한국 시청자 대상 채널에 올릴 때 문제가 되는지는 판단 못 함 — H3 대신 LTX-2.5만 쓰는 쪽이 안전해 보인다(추정). 일부 이미지 모델(Ideogram 4 등)은 비상업용.
- 익명 사용 통계가 기본으로 켜져 있다(설정에서 끌 수 있음).

### 2. WyattBlue/auto-editor
링크: https://github.com/WyattBlue/auto-editor  ⭐ 6,202 · 최근 push 2026-11-28 (퍼블릭 도메인)

**뭐 하는 건데:** 영상 오디오 크기(또는 움직임)를 분석해 말 없는 구간을 자동으로 잘라낸 영상을 만들거나, 자른 결과를 Premiere·DaVinci Resolve·Final Cut Pro용 타임라인 파일로 내보낸다. 앞뒤 여백(`--margin`)과 임계값을 조절할 수 있다. (README 확인)

**미아한테 왜:** 비전에셋tv 원본 촬영본에서 말 사이 공백·머뭇거림을 손으로 잘라내는 1차 컷 작업을 `auto-editor 원본.mp4` 한 줄로 대신한다. Claude Code에 폴더째 넘겨 일괄 처리시키기도 쉽다.

**바로 해볼 것:** Claude Code에 "auto-editor 맥에 설치하고 이 촬영본을 --margin 0.3s로 돌려줘"라고 시킨 뒤 결과 영상을 원본과 비교한다.

**걸리는 점:**
- 맥 설치 방법은 auto-editor.com의 설치 문서로 안내되어 있는데, 이번 세션에서 그 사이트에 접근이 안 돼 확인 못 했다.
- CapCut용 내보내기는 README 목록에 없다. CapCut에서 마무리할 거면 잘린 MP4 결과물을 가져다 쓰는 방식이 된다.
- 소리 크기 기준이라 배경음악이 깔린 영상이나 시끄러운 현장 촬영(매물 투어)에서는 잘 안 맞을 수 있다(추정). 이전에 브리핑한 kajisho5/ffmpeg-skill로도 비슷한 걸 시킬 수는 있지만, 이쪽이 무음 컷 전용으로 다듬어져 있다.
